# 信小递管理端设计系统规范（统一 skill 管理端规则层）

> **本文件是管理端「业务规则」的唯一事实源。** 色值 / 组件 / 图标一律用本 references 目录里与司机端**共用**的核心（`tokens.json` / `ui.css` / `components/*.json` / `assets/`），本文件不重复维护，也不得另立标准。
>
> 使用前先经 SKILL.md「闸门 0 · 端识别」判定为**管理端**，再读本文件。

---

## 0. 定位：管理端 vs 司机端

信小递有两个端，**同一套设计系统核心，不同的业务视角**：

| 维度 | 司机端 | 管理端（本规则层） |
|------|--------|-------------------|
| 使用者 | 司机本人（执行者） | 业务方管理者（调度 / 监管 / 审核） |
| 数据范围 | 只看**自己**的任务 | 看**跨司机 / 跨车辆 / 跨订单**的全局单据 |
| 核心动作 | 执行：到库登记、提货、签收、拖车作业 | 管理：下达、派发、改派、审核、监管、介入异常 |
| 首页 | 金刚区首页（`demo-home`） | **金刚区首页**（`admin-home`，六模块入口，见 §3.0） |
| 页型 | 登录 / 首页 / 功能选择 / 列表 / 操作 / 弹窗 | 金刚区首页 + 列表页 + 详情页 + 弹窗 的组合 |

**内容差异的通用规律**（同一组件，管理端要多带「谁 / 哪辆车 / 什么状态 / 管理动作」）：

- 列表卡片：司机端隐含「我」；管理端**必须显式带**承运司机 / 车牌 / 所属网点 / 客户，用于区分不同对象。
- 操作按钮：司机端是「我去执行」（到库登记 / 提货打卡）；管理端是「我来管理」（派单 / 改派 / 审核通过 / 驳回 / 介入）。
- 详情页：司机端偏「录入 + 提交」（含上传）；管理端偏「只读全量展示 + 审核 / 处置动作」，上传类动作仅在回单上传等少数场景保留。

## 1. 设计系统核心（与司机端共用，不重复定义）

以下全部用本 references 目录里与司机端**共用**的核心文件，本文件不复制数值：

- **色板 / 语义 token / 间距 / 圆角 / 控件尺寸** → `tokens.json`
- **可运行样式 class** → `ui.css`
- **组件白名单与用法** → `components/*.json`
- **图标 SVG** → `assets/`

**速记（与司机端一致，仅供快速核对，权威值仍看 tokens.json）：**

- 品牌主色 `#00AAA6`（primary-6）；悬浮 `#22BBB3`，按下 `#009093`。
- 文字：主 `#1D2129`、次 `#4E5969`、辅助 `#86909C`、占位 `#C9CDD4`。
- 填充：卡片白 `#FFFFFF`、页面背景 / 卡片内嵌区 `#F2F3F5`。
- 功能色：成功 `#00B42A`、警告 `#FF7D00`、危险 `#F53F3F`、信息 `#165DFF`。
- 字体 PingFang SC，按钮文字 Regular(400)。
- 间距 4 基数（4/8/12/16/20/24/28/32/40/48）；圆角 tag2 / control4 / dialog8 / card10 / icon-bg12 / pill999。

## 2. 标签色语义映射（沿用司机端，不新增语义）

管理端标签色**承载与司机端相同的业务语义**，不得为了区分模块而改色：

| 标签色 | class | 语义（两端一致） |
|--------|-------|------------------|
| 蓝 `#165DFF` | `.tag--blue` | 运单 / 提货点 / 运单状态 |
| 橙 `#FF7D00` | `.tag--orange` | 2C / 收货点 / 约定时间 |
| 紫 `#722ED1` | `.tag--purple` | 电商补货 |

**单据状态**用文字标签 + 功能色文字（不滥用彩色底）：

- 待处理 / 待派发 → 信息蓝 `#165DFF` 或中性；进行中 → 品牌绿 `#00AAA6`；异常 / 驳回 → 危险红 `#F53F3F`；已完成 / 已签收 → 成功绿 `#00B42A` 或置灰。
- 状态色只承载「单据处于什么阶段」，不与上面的业务标签色语义混用。

## 3. 页型语义（管理端用金刚区首页 + 三类页型）

### 3.0 金刚区首页（管理端入口）

**用途**：业务方登录后的统一入口，聚合金刚区入口。参考成品 `examples/admin-home.html`（已按 Figma 还原）。

**组成**（从上到下，按 Figma）：状态栏(44，白字) → 标题栏「信小递」(44，透明底 + 胶囊) → 绿色渐变头部（头像 + 「您好，欢迎使用信小递」）→ **白卡一：金刚区 4 列网格（6 个业务入口）** → **白卡二：「预警预控」分组（超期预警 1 个入口）** → 底部 Home Indicator。**无**快捷卡（待派单/待审核）、**无**待办任务列表。

**金刚区规则**：

- **白卡一 6 个业务入口** = 订单管理 / 运单管理 / 调度单管理 / 签收管理 / 回单上传 / 拖车业务（4 列，第一行 4 个 + 第二行 2 个）。
- **白卡二「预警预控」分组** = 超期预警（独立白卡，卡内左上角标题「预警预控」+ 下方入口）。
- 每个入口图标用 **`assets/shortcuts/icon/home/oa/` 下的彩色图标**（自带渐变底，与 Figma 一致）：`dingdan.svg`(订单) / `yundan.svg`(运单) / `diaodudan.svg`(调度单) / `qianshou.svg`(签收) / `huidan.svg`(回单上传) / `tuoche.svg`(拖车业务) / `yujing.svg`(超期预警)。**不要用 `shortcuts/` 根目录的单色版**。禁止 emoji / 自造图标。
- 渐变头部、白卡圆角、网格沿用司机端 `demo-home` 骨架，**不整块重画首页**。
- **超期预警**：监控超期 / 临期运单，卡片带 运单号 / 承运司机+车牌 / 超期时长 / 客户，动作 `催办`、`异常介入`、`详情`；页型为列表页 + 详情页。

**两端重名 / 同域入口（未说端必消歧，见 SKILL.md 闸门 0）**：「回单上传」「拖车业务」与司机端**同名**；「签收管理↔待签收」「超期预警↔异常提报」与司机端**同域**。用户只提名称未说端时，**先问是司机端还是管理端**，不得默认按管理端做。

**首页入口歧义必问**（对应 SKILL.md 闸门 2）：新模块接入首页时，是「金刚区新增一个入口」还是「进现有某入口的列表页里加筛选/动作」，需求没说清必须先问。

### 3.0b 功能选择页（Hub）

**用途**：某模块含多个子功能时的二级入口页（如**拖车业务** → 派车 / 业务监控）。参考成品 `examples/admin-trailer-hub.html`。

**组成**：状态栏 → 标题栏（返回 + 模块名 + 胶囊）→ 白卡（顶部浅绿渐变）内**功能球网格**（`trailer-item`：白底圆角方块 + 44px 图标 + 标签 + 右上角红色数字角标）。骨架复用司机端 `demo-trailer.html`。子功能图标用 `assets/icons/tuoche/*.svg`（自带浅绿圆底）。

### 3.1 列表页（管理端最核心）

**用途**：业务方浏览 / 筛选 / 批量管理某一类单据。

**组成**（从上到下）：状态栏(44) → 标题栏(44，带模块名 + 返回) → 搜索框(36) → Tab 状态分组(30，可选) → 单据卡片列表(卡片间距12) → 浮动按钮(可选，如「新建 / 批量派单」)。

**卡片内容规则**（管理端专属，用司机端 `.card` + `.card__*` 拼装）：

- 顶部：业务标签（`.tag--blue` 等）+ 关键单号 / 地址（`.card__addr`）。
- **必带管理维度**：承运司机、车牌号、所属网点 / 客户之一或多个（司机端可省，管理端不可省）。
- 中部：货品 / 数量 / 时间等业务字段。
- 底部：左侧统计，右侧管理动作按钮组（派单 / 改派 / 审核 / 详情）。
- 多单据分组（订单→调度单→运单三层）沿用司机端收起 / 展开结构。

### 3.2 详情页

**用途**：查看单据全量信息 + 执行管理动作。

**组成**：状态栏 → 标题栏（单据名 + 返回）→ 只读信息卡（字段 label-value，内嵌区用 `#F2F3F5`）→ （可选）关联单据列表 → 底部固定操作栏 + 大按钮（审核通过 / 驳回 / 改派 / 介入等）。

**与司机端差异**：司机端详情页常含拍照 / 上传 + 提交（`uploader`）；管理端详情页**以只读展示 + 审核 / 处置为主**，仅回单上传等少数模块保留 `uploader`。

### 3.3 弹窗/面板

**用途**：轻量管理动作（≤ 2 步），如派单选司机 / 车辆、签收核验、回单补传、异常介入备注。

- 居中确认 / 轻表单 → `.dialog`（复用司机端 `demo-trailer-weighing` / `demo-trailer-reschedule` 的 dialog 结构）。
- 选择类（选司机 / 选车辆 / 选时间）→ `.sheet` 动作面板 / 滚轮（复用司机端 sheet 组件），不用居中 dialog 代替选择。

## 4. 六大模块业务规则

> 每个模块都是「列表页 + 详情页 +（可选）弹窗」的组合，统一从金刚区首页进入。字段与按钮为规则约定，具体路由与复用底板见 `scenario-map-admin.json`。

### 4.1 订单管理

- **列表页**：客户订单列表。卡片带 客户名称 / 订单号 / 收发货地址（`.tag--orange` 收货点）/ 货品概要 / 订单状态。动作：`详情`、`拆分调度`。
- **详情页**：订单全量（客户信息、货品明细、地址、时效要求）+ 关联调度单列表。动作：`生成调度单`。
- Tab 分组建议：全部 / 待调度 / 调度中 / 已完成 / 异常。

### 4.2 运单管理

- **列表页**：跨司机运单监管列表。卡片带 运单号（`.tag--blue`）/ 承运司机 + 车牌 / 起讫点 / 当前节点状态。动作：`详情`、`异常介入`。
- **详情页**：运单轨迹 / 节点时间线（只读）+ 司机 / 车辆信息 + 货品。动作：`介入处理`、`联系司机`。
- Tab 分组建议：全部 / 待提货 / 运输中 / 待签收 / 已签收 / 异常。

### 4.3 调度单管理

- **列表页**：调度单列表。卡片带 调度单号 / 关联订单 / 计划司机 + 车辆（未派则显示「待派单」）/ 货品 / 计划时间。动作：`派单`、`改派`、`详情`。
- **派单 / 改派弹窗**：`.sheet` 选司机 + 选车辆（或 dialog 表单）；改派需备注原因。
- **详情页**：调度单全量 + 关联运单列表 + 派发记录。
- Tab 分组建议：全部 / 待派单 / 已派单 / 执行中 / 已完成。

### 4.4 签收管理

- **列表页**：签收核验列表。卡片带 运单号 / 客户 / 承运司机 + 车牌 / 签收状态（正常 / 异常签收）/ 签收时间。动作：`核验`、`详情`。
- **详情页**：签收信息 + 司机回传的签收凭证（图片只读预览）+ 差异说明。动作：`确认签收`、`标记异常`。
- **核验弹窗**：确认 / 驳回 + 备注（dialog）。
- Tab 分组建议：全部 / 待核验 / 已确认 / 异常签收。

### 4.5 回单上传

- **列表页**：回单待办列表。卡片带 运单号 / 客户 / 回单类型 / 上传状态（待上传 / 已上传 / 待审核）。动作：`上传`、`详情`、`审核`。
- **上传弹窗**：`uploader` 组件（本模块保留上传）；选择回单类型 + 上传照片 + 提交。
- **详情页**：回单凭证预览 + 审核动作（通过 / 驳回 + 备注）。
- Tab 分组建议：全部 / 待上传 / 待审核 / 已通过 / 已驳回。

### 4.6 拖车业务（管理端侧）

- 按 Figma：管理端拖车业务的入口是**功能选择页(Hub)**（成品 `examples/admin-trailer-hub.html`），仅含两个子功能，各带待办数红角标：**派车**、**业务监控**。从首页金刚区「拖车业务」进入本 Hub，再进各子功能列表。
- **列表页模板**（成品 `examples/admin-trailer-list.html`，Figma 7532:87598）：**派车**与**业务监控**两个列表页共用同一模板，仅换标题 / 字段 / 按钮：
  - 结构：绿头（返回 + 标题 + 胶囊）+ **带筛选搜索框**（`.searchbox`：用柜需求筛选下拉 + 查询）+ **场站切换**（青岛振翔 ▼）+ **用柜需求卡片列表**。
  - **用柜需求卡片**（用组件库类拼装）：`.card` + `.card__order-top`（浅绿头条：`.card__waybill-label`「用柜需求号」+ `.card__order-sap` 编号）+ `.card__body` 内 `.card__field`（`.card__field-label` + `.card__field-value`：船务公司 / 订单号 / 船名航次 / 截港时间）+ `.card__waybill-actions` >  `.btn.btn--sm.btn--primary`（右下操作）。
  - **派车**：按钮=`派车`；**业务监控**：标题=业务监控、按钮=`详情`/`异常介入`，可按需增减字段。
- 拖车字段（柜号 / 订舱号 / 场站 / 装货点等）与司机端一致，见 `components/card.json.pageFieldConfig`。

## 5. Agent 消费速查（产出管理端页面时照做）

1. **先经端识别闸门判为管理端**（SKILL.md 闸门 0），再读本文件。
2. **判页型**：管理端任何一屏落在 金刚区首页 / 列表页 / 详情页 / 弹窗 之一。
3. **找底板**：因组件与司机端完全相同，先在 `examples/` 找同页型底板（首页→`admin-home`；功能选择页→`admin-trailer-hub`；列表→`demo-list` / `demo-trailer-*`；详情→`demo-trailer-detail`；弹窗→`demo-trailer-weighing` / `demo-trailer-reschedule` / `demo-interaction`），复制微调。
4. **换管理端内容**：把司机端「我执行」的字段 / 按钮换成管理端「谁 + 管理动作」（见 §0、§4）。
5. **动作归属存疑就问**（SKILL.md 闸门 2）：页面级还是卡片级？是否需二次确认弹窗？
6. **引用核心**：`ui.css` / `assets` 用本 references（相对原型路径回指，如 `../ui.css`）。
7. **产出后自检**：跑 `scripts/verify-prototype.mjs`（默认 `--ds references`）。

## 6. 常见错误（出现即返工）

- ❌ 为管理端另存一份 tokens/ui.css/assets → 与司机端共用同一份，单一事实源。
- ❌ 为区分模块自造标签色 / 状态色 → 标签色语义两端一致，状态用功能色。
- ❌ 管理端列表卡片不带承运司机 / 车牌 / 客户 → 管理端必须能区分对象。
- ❌ 详情页照搬司机端的「拍照 + 上传 + 提交」→ 除回单上传外，管理端详情以只读 + 审核为主。
- ❌ 把选司机 / 选车辆做成居中 dialog → 选择类用 sheet 动作面板 / 滚轮。
- ❌ 管理端首页金刚区改成 emoji / 自造九宫格 / 去掉渐变头部 → 沿用 `admin-home` 骨架，只换入口图标 + 文案。
