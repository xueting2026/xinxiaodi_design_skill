# 信小递设计系统 Skill（司机端 + 管理端）

海信物流「信小递」**微信小程序**的机读设计系统，覆盖**两个端**：**司机端**（司机本人执行任务）与**管理端**（业务方对司机 / 单据进行管理）。两端**共用同一套设计系统核心**（token / ui.css / 组件 / 图标 / 自检脚本），**业务规则层各自独立**。本 skill 的头等职责是——**产出可交付给开发的移动端 HTML 原型**。你的工作是**执行这套规范，不是自由发挥**。

- **平台**：微信小程序（移动端）。**设计宽度 375px**（iPhone X），**内容宽度 343px**（左右各 16px 边距）。两端一致。
- **品牌色 `#00AAA6`**（primary-6 / brand）。**字体唯一 PingFang SC**，按钮文字统一 Regular(400)。
- 设计性格：简洁实用、卡片圆角、克制色彩、清晰层级、操作效率优先。

## 🚦 最高优先级：两阶段门（先确认《原型方案》，再产出 HTML）

**任何「产出 demo / 生成页面 / 出原型」的需求，必须分两个回合完成，禁止在同一轮里既给方案又出 HTML。**

| 阶段 | 你要做的 | 你**禁止**做的 |
|---|---|---|
| **阶段一（本轮）** | ① 端识别（闸门 0）② 有限轮澄清（最多 1–2 轮，一次性打包问；输出模式默认 demo，不问，见闸门 1）③ 逐屏场景匹配评估 → 汇总成一份**《原型方案》** → **请用户确认或修改** → **结束本轮回复，停下等待** | ❌ 生成 / 写任何原型 HTML 文件<br>❌ 在同一条回复里继续进入产出<br>❌ 说「已确认，我继续」自问自答 |
| **阶段二（用户确认后的下一轮）** | 按已确认的《原型方案》逐屏产出 HTML → 机械自检（`verify-prototype.mjs`）→ 交付 | ❌ 偏离已确认方案（要改先说明并重新确认该屏） |

**《原型方案》必含**（在对话里呈现，默认不落文件，与"评估结论不写进 HTML"一致；用户要存档可写入其工作目录）：

1. **端**：司机端 / 管理端（含判定依据）。
2. **模式**：默认 demo 演示（不问；仅当用户显式要求交付开发时才注明）。
3. **页面清单**：每屏一行 → `屏名 · 页型 · 复用底板 · 重合度档位（高/低/零）`。
4. **每屏关键内容**：关键字段 / 卡片维度 / 主要动作（管理端需注明承运司机·车牌·客户与管理动作）。
5. **待确认假设与缺口**：合理默认假设（标注）、零重合项的《缺口报告》、需用户拍板的歧义点（闸门 2）。

**判定「已确认」的唯一标准**：用户在**看到《原型方案》之后**给出明确肯定答复（「确认」「可以」「按这个做」「开始」）。以下都**不算**确认：用户最初那句需求、对澄清问题的回答、还没看到方案就说的「继续」、你自己推断"应该没问题"。

**唯一可跳过本门的情形**（从严解释，拿不准就走门）：① 已确认方案下的增量（加 / 改一个方案里已写清的屏）；② 纯数据 / 文案 / 图标 / 单点样式微调；③ 用户**显式**要求「不用出方案，直接做」。

> 违反表现：一轮回复里既给了《原型方案》又写出了 `xxx.html` —— 这是**错误**，必须避免。阶段一只对齐，不动手。

## 一条铁律（两端通用）

**值只从 `references/tokens.json` 取；颜色只用语义 token（`color-text-*`/`color-fill-*`/`brand`…）；间距 / 圆角 / 字号 / 控件尺寸只用既定档位——绝不裸写像素、绝不自造色、绝不自造组件、绝不加规范外装饰。**

## 🚨 组件复用铁律（最高优先级）

**所有原型必须引用 `references/ui.css`，并使用其中定义的 CSS class 构建组件。**

- `references/preview/` 与 `references/examples/` 里的组件是经过精心调教的标准实现。
- 生成页面时，**禁止用纯内联 style 重新实现任何已有组件**。
- 若某 UI 元素在 `ui.css` 中有对应 class，必须使用该 class。
- 仅对组件 JSON 中定义的「card 内部结构」等页面特定布局可用内联样式补充。
- **不确定用什么组件 → 必须询问用户，不允许自行发挥。**
- **两端共用同一份核心**：管理端不得为自己另存一份 tokens/ui.css/assets 副本。

违反此规则 = 交付失败，必须返工。

## 消费顺序（每次任务照做）

0. **端识别**（闸门 0）→ 确定司机端 / 管理端，加载对应规范与场景路由。
1. **取值** → `references/tokens.json`：单一事实源（颜色/字体/间距/圆角/组件尺寸）。两端共用，直接引用，不改不近似。
2. **取规则** →
   - 司机端：`references/Design.md`（司机端唯一规范文档）。
   - 管理端：`references/Design-admin.md`（管理端业务规则层：金刚区首页 + 六模块）。
   **先读对应的那份。**
3. **看组件** → `references/components/*.json`（组件元数据 + `cssClasses` 白名单 + `usageScenarios`，两端共用）与 `references/preview/*.html`。
4. **取素材** → `references/assets/`（两端共用 SVG 图标、Logo；管理端金刚区入口图标见 `assets/shortcuts/*_mgmt.svg` 等）。
5. **取路由** →
   - 司机端：`references/scenario-map.json`
   - 管理端：`references/scenario-map-admin.json`
6. **看成品** → `references/examples/*.html`（司机端 `demo-*`；管理端 `admin-*`）。

## 生成任何页面前必问（两个行为闸门）

### 闸门 1 · 输出模式（默认 demo，**不再询问**）

**信小递原型默认只做 demo 演示，不必再问 demo / 交付。** 除非用户**显式**要求"交付开发 / 响应式 / 出 rpx"，一律按 demo 处理。

- **demo 演示（默认）** → 固定宽度 375px 手机框，保持现有 CSS 不变。demo 里凡 `position:fixed` 的浮层（弹窗蒙层 `.dialog-overlay`、浮动按钮 `.fab`、动作面板 `.sheet-overlay`）要在 `#app` 作用域改成 `position:absolute`，收敛到 375px 手机框内，不溢出浏览器视口。
- **交付开发（仅用户显式要求时）** → 改响应式：宽度 `100% + max-width:750px`（px×2=rpx），内容区 `calc(100% - 32px)`，其余高度 / 间距保持 px。

### 闸门 2 · 入口 / 动作归属歧义必问

- **司机端**：新功能在首页如何接入没说清 → 必问：① 首页金刚区**新增功能球**？② **现有功能球里改**（复用入口）？两种都直接引用 `examples/demo-home.html`，绝不整块重画首页。
- **管理端**：① 新模块接入首页金刚区是「新增入口」还是「进现有入口列表页加筛选/动作」，没说清必问；② 管理动作是**页面级**（列表顶部/详情底部）还是**卡片级**（每条单据上），是否需二次确认弹窗，存疑必问。两端首页都不整块重画（不得把金刚区改成 emoji、不得自造九宫格、不得去掉渐变头部）。

## 场景匹配评估流程（阶段一的核心，产出《原型方案》的依据）

依据当前端对应的 `scenario-map*.json`，**逐屏**判断页型与重合度。这一步的结论就是《原型方案》的第 3、4、5 项——**在对话里向用户汇报并请确认，不要写进 HTML**（产品经理看到的原型要保持干净，无过程注释）。**评估完即停下等确认，不在本轮继续产出**（见顶部两阶段门）。

| 档位 | 判据 | 路由 |
|------|------|------|
| **高重合** | 命中某 examplePage 页型，核心区块覆盖 ≥ 70% | 以该 example 为底板**复制微调** |
| **低重合** | 无现成成品页，但所需区块都能在 components 找到 | 用 components 组件 + `ui.css` class **逐块拼装** |
| **零重合** | 页型无成品页，核心区块在 components 也无对应 | **停止生成**，输出《缺口报告》，询问用户 (A) 补齐后再做 / (B) 同意自由发挥（标记为非规范）。未得答复不得擅自发挥。 |

- **高重合微调允许范围**：替换数据/文案/图标；隐藏或删除当前场景用不到的子元素；增减列表项；复用组件已有状态类。**禁止**改组件 DOM 骨架、重写组件样式、加规范外装饰。
- **低重合**：每一区块都要能追溯到某个组件 slug；禁止自造组件、禁止引用 examples 里未回收的页面私有 class。
- **管理端提示**：因两端组件完全相同，管理端大多数屏会与司机端 examples 高重合——优先复制司机端底板（`demo-list` / `demo-trailer-detail` 等）再替换为管理端业务内容（承运司机 / 车牌 / 客户 + 管理动作）。

《原型方案》汇报格式示例（阶段一末尾输出，然后停下等确认）：
> **原型方案**
> - 端：管理端（依据触发词"派单/调度单管理"）
> - 模式：demo 演示
> - 页面清单：
>   1. 管理端首页 · 金刚区首页 · 底板 admin-home · 高重合
>   2. 调度单列表 · 列表页 · 底板 demo-list · 高重合
>   3. 派单弹窗 · 弹窗/面板 · 底板 demo-interaction(sheet 选司机/车辆) · 高重合
> - 关键内容：调度单卡片带 调度单号 / 关联订单 / 计划司机+车辆 / 计划时间；卡片动作 派单·改派·详情
> - 待确认：派单是卡片级还是列表页批量？（闸门 2）默认按卡片级处理，请确认。
>
> 以上方案可以吗？确认后我按此逐屏产出并自检。

> ⚠️ 输出方案后**必须停下**，等用户明确确认再进入阶段二产出，**不要在本轮直接生成 HTML**。

## 产出后强制校验（机械自检，非声明）

原型产出后，必须逐条**实际核对**（不是口头声明"已复用"）。任一未过即为交付失败，必须返工：

1. **权威源**：原型引用的样式必须指向本 skill 的 `references/ui.css`。
2. **class 白名单**：抽取原型里所有 `class="..."`，逐个在 `ui.css` 与组件 JSON 的 `cssClasses` 里查；查不到 = 疑似自造（页面级布局类会列为 WARN，属预期），必须改用组件类，或在零重合流程里显式报备。
3. **图标**：所有 `<img src>` 必须落在 `references/assets/` 下，不使用自创内联 SVG 图标。
4. **不留过程注释**：HTML 里不写场景评估 / 路由决策等过程性注释；只在对话中向用户汇报。

**用自检脚本执行**（零依赖 Node，位于本 skill 内，两端通用）：

```bash
node .kiro/skills/xinxiaodi-design/scripts/verify-prototype.mjs <原型HTML的绝对路径>
```

脚本默认 `--ds references`（本 skill 内的设计系统目录）。有任一 ERROR → 退出码 1，必须返工；WARN 需人工确认。

## 页型速查

**司机端**（详见 `references/Design.md`）：

| 页型 | 何时用 | 参考成品 |
|------|--------|----------|
| 登录页 Auth | 身份认证 | `examples/login.html` |
| 首页 Home | 概览全局 / 功能入口 | `examples/demo-home.html` |
| 列表页 List（最核心） | 浏览/筛选/批量操作 | `examples/demo-list.html`、`examples/demo-pending-arrival.html` |
| 搜索页 Search（**共用**） | 点列表页搜索框进入，即时搜索 + 命中词高亮，含 默认/无结果/结果(1行·2行) 四态 | `examples/demo-search.html` |
| 操作页 Action/Form | 针对某对象录入并提交 | `examples/demo-trailer-*.html` |
| 弹窗/面板 Dialog | 操作 ≤ 2 步、轻量 | `examples/demo-interaction.html` |

**管理端**（详见 `references/Design-admin.md`）：

| 页型 | 何时用 | 参考成品 |
|------|--------|----------|
| 金刚区首页 | 业务方统一入口（六模块） | `examples/admin-home.html` |
| 列表页（最核心） | 浏览/筛选/批量管理单据 | 司机端 `demo-list.html`；拖车列表模板 `admin-trailer-list.html`（用柜需求卡片）；通用单据列表模板 `admin-order-list.html`（订单/运单/调度单等通用字段） |
| 功能选择页/Hub | 模块多子功能的二级入口 | `admin-trailer-hub.html` |
| 搜索页（**共用**） | 点列表页搜索框进入，即时搜索 + 命中词高亮 | `demo-search.html`（两端共用，同一成品） |
| 详情页 | 单据全量 + 审核/改派/介入 | 司机端 `demo-trailer-detail.html` 作底板 |
| 弹窗/面板 | 派单/核验/上传等轻动作 | 司机端 `demo-trailer-weighing.html` / `demo-interaction.html` 作底板 |
